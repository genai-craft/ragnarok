# 既存手法との比較 (2026-10-02)

数値はすべて同じ条件で自分たちが測ったもの (FinanceBench open-source 150 問 / 10-K 84 冊、埋め込み Qwen3-Embedding-0.6B、判定・回答・採点は Qwen3.8-27B-AWQ-INT4 ローカル、GPU 1 枚)。
PageIndex 公称の 98.7% は GPT-4o 回答 + 人手判定の自社ベンチなので、ここには混ぜない。

## 1. 検索 (どのページを渡すか) — 根拠ページの的中率

| 手法 | 分類 | 根拠 hit@1 | 根拠 hit@5 | 回答正解率 (同じ 27B 回答器) | 1 問あたりのモデル呼び出し |
|---|---|---|---|---|---|
| ベクトル検索のみ (ページ埋め込み) | 既存 | 0.36 | 0.67 | 0.47 | 0 (埋め込みのみ) |
| + cross-encoder rerank (bge-reranker-v2-m3、top-50) | 既存 | 0.28 | 0.61 | 0.46 | 50 forward (候補ごと) |
| + 生成型 listwise rerank (RankGPT 方式、27B が top-25 の順位を書く) | 既存 | 0.57 | 0.81 | 0.59 | 1 回の生成 (~100 token) |
| PageIndex 方式 (木を見せて節 id を生成、レイアウト木 + 要約) | 既存 | 0.39 | 0.58 | 0.45 | 1 回の生成 |
| 木を確率判定で辿る (jev-rag の木モード) | 本件 | 0.21 | 0.31 | 0.22 | ~3 |
| **ベクトル + 確率判定 rerank 2 段 (jev-rag 既定)** | 本件 | 0.59 | **0.88** | **0.66** | 3 forward × 1 token |
| 同上 + 回答器を思考あり | 本件 | 0.59 | 0.88 | **0.73** | 同上 + 回答 |
| 同上の 4B 版 | 本件 | 0.57 | 0.77 | 0.53 | 3 forward (4B) |

- cross-encoder は 10-K のページ (表だらけ・長い) に弱く、埋め込み単体より落ちた。
- 生成型 rerank は良いが、1 token の確率判定 2 段に hit@5 で 7pt、正解率で 7pt 負ける。しかも確率と「どれでもない」が出ない。
- 木 (PageIndex 方式も、確率判定で辿る版も) は FinanceBench 型 (表の中の数値) では不利。木が効くのは構造が意味を持つ文書・質問 (後述)。

## 2. 棄却 (その文書に答えが無いときに言えるか)

| 相手の文書 | 埋め込み類似度の閾値 (既存) AUROC | jev-rag「どれでもない」確率 (27B) AUROC | 27B を none>0.5 で: 誤棄却 / 棄却 |
|---|---|---|---|
| 別会社の 10-K (150 問) | 0.993 | 0.985 | 3% / 90% |
| **同じ会社・3 年以上離れた 10-K (70 問)** | **0.731** | **0.960** | **1% / 79%** |

埋め込みは「似た文書」を見分けられない。生成型 rerank・PageIndex・GraphRAG は棄却の数値を持たない (必ず何かを返す)。

## 3. 木の探索の比較 (合成 QA 174 問、アウトライン付き PDF 5 冊、正解 = 節)

| 手法 | hit@1 | hit@3 |
|---|---|---|
| PageIndex 方式 (木を見せて id 生成、27B) | 0.36 | 0.48 |
| 木を確率判定で辿る (27B) | 0.46 | 0.59 |
| 節のベクトル検索 | 0.53 | 0.78 |
| ベクトル + 確率判定 rerank (27B) | **0.57** | **0.85** |

同じ木でも「生成で id を書かせる」より「確率判定で降りる」方が良い。が、節の本文の埋め込みの方がさらに良く、組み合わせが最良。

## 4. 向き不向き (定性)

| | ベクトル RAG | + cross-encoder | + 生成型 rerank | PageIndex (木) | GraphRAG | **jev-rag** (ベクトル + 確率判定 + 木の補助) |
|---|---|---|---|---|---|---|
| インデックスのコスト | 埋め込みのみ (安) | 同左 | 同左 | 全ページに LLM (約 $1/1000 頁、数分) | 全チャンクに LLM 抽出 + コミュニティ要約 (最も高い) | 埋め込み + 任意で木 (レイアウトなら LLM なし) |
| 質問ごとのコスト | 最小 | 候補数 × forward | 生成 1 回 (長い出力) | 木を降りる生成を数回 | ローカル/グローバル検索 + 要約 | 1 token の判定 2〜3 回 (生成なし) |
| 必要なモデル | 埋め込み | + 小型 reranker | + LLM | LLM (推奨は最上位クラス) | LLM 大量 | 埋め込み + 27B 級 (4B は精度落ち) |
| 長い 1 文書の中のピンポイント (財務諸表の数値) | ○ | △ (表に弱い) | ○ | △ (表は見出しに出ない) | △ | **◎** (測定で最良) |
| 構造を跨ぐ参照 (「第 3 条の例外は第 7 条に」「表 5 の脚注」) | △ | △ | △ | **◎** (独立検証でも木が勝つ領域) | ○ | ○ (木を補助に使えるが未測定) |
| 多数文書の横断 (コーパス全体から) | **◎** | ◎ | ○ | △ (木を全部見るのは不利) | ○ | ◎ (ベクトルで文書を絞る) |
| 関係・集約の質問 (「この人物と関わる案件は」「全体の傾向は」) | △ | △ | △ | △ | **◎** (グラフの本領) | ○ (集約は網羅モードで再現率 0.93、関係は未測定) |
| 文書に無い質問の棄却 | △ (類似度閾値、似た文書に無力) | △ | × (必ず返す) | × (必ず降りる) | × | **◎** (該当なしの確率、同社別年度 AUROC 0.96) |
| 確率・確信度が出る | 類似度のみ | スコアのみ | × | × | × | ◎ (校正可能な分布) |
| 根拠の説明性 | ページ/チャンク | 同左 | 順位 | 節の経路 (良い) | グラフの経路 (良い) | ページ + 節の経路 + 各候補の確率 |
| 日本語 | 埋め込み次第 | reranker 次第 | LLM 次第 | 英語中心 (公式) | LLM 次第 | 埋め込み・判定とも日本語可 (4B 判定は要校正) |
| 完全ローカル | ○ | ○ | ○ | △ (ローカル版も LLM は API 前提) | ○ (高コスト) | **◎** (GPU 1 枚で全部) |

## 5. 集約 (「X に触れている箇所を全部」) — 網羅性 (2026-10-02 追加)

10-K 6 冊 × 8 話題 (自社株買い・減損・気候変動・サイバー・年金・訴訟・株式報酬・為替) = 45 件。正解 = 27B に全ページを yes/no 判定させた oracle (平均 7 ページ/話題)。
GraphRAG のグローバル検索が狙う「取りこぼさない」を、事前抽出なしに質問時の判定でどこまで出せるか。bench/fb_agg.py。

| 手法 | 再現率 | 適合率 | F1 | 判定の呼び出し/問 |
|---|---|---|---|---|
| ベクトル top-10 (既存の常套) | 0.57 | 0.48 | 0.52 | 0 |
| ベクトル top-20 | 0.71 | 0.32 | 0.45 | 0 |
| キーワード一致 | 0.80 | 0.57 | 0.67 | 0 |
| ベクトル top-50 → 4B yes/no で絞る | 0.82 | 0.66 | 0.73 | 50 (4B、合計 ~1.5 s) |
| ベクトル top-50 → 27B yes/no で絞る | 0.86 | 0.997* | 0.92* | 50 (27B) |
| **全ページ → 4B yes/no (網羅モード)** | **0.93** | 0.61 | 0.74 | 155 (4B、合計 ~4 s) |

\* oracle も 27B の判定なので 27B の適合率は構造的に高く出る (同じ審判)。4B の行が独立した数字。
- ベクトル top-k は「全部拾う」用途に向かない (k を増やすと適合率が落ちるだけ)。判定で絞る/全ページを判定すると再現率 0.57 → 0.82〜0.93。
- 全ページ判定は 1 ページ 25 ms の 4B で 10-K 1 冊 4 秒。GraphRAG の事前抽出 (全チャンク LLM 生成) なしに、質問時だけで網羅できる = 「遅延グラフ」の土台。
- 残る弱点: 関係そのもの (A と B の繋がり) や複数文書の俯瞰は未測定。向き不向き表の「関係・集約」は △ → ○ (集約は測って勝ち、関係は未測定) に更新。

### 使い分けの結論
- **大量の雑多な文書から探す** → ベクトル RAG。精度が要るなら jev-rag の確率判定 rerank を後段に挿す (生成型 rerank より速く、確率が出る)。
- **長い定型文書 (有報・契約・マニュアル) からピンポイントに引く、答えが無いときは無いと言ってほしい** → jev-rag。
- **条項や表の参照関係、構造そのものが問いになる** → 木 (PageIndex 方式か jev-rag の木モード)。ただし今回の測定では表の数値には弱い。
- **人物・組織・事象の関係や全体傾向** → GraphRAG。選択の段 (エンティティ同定・コミュニティ選択) には jev-rag の確率判定を流用できるが、抽出コストは減らない。
